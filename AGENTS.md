## Environment & Configuration

- **Required production env vars** (validated at startup): `NODE_ENV=production`, `APP_URL`, `LIFEOS_DATA_DIR`, `LIFEOS_AUTH_REQUIRED=true`, `LIFEOS_AUTH_EMAIL`, `LIFEOS_AUTH_PASSWORD_HASH`, `LIFEOS_VAULT_SECRET` (≥32 non-placeholder chars).
- **`loadEnv.ts` loads `.env.local` first**, then root `.env`. It must remain the very first server import — every persistent artifact (SQLite, vault, vector memory, backups) observes `LIFEOS_DATA_DIR` from these files.
- **`.env.example`** template exists; never commit real values.
- **Data directory**: All persistent artifacts are rooted below `LIFEOS_DATA_DIR`. In development it defaults to `./data`; in production it must be an absolute path on a stable device.
- **Vault encryption**: Provider keys (NVIDIA, OpenAI, Gemini, GitHub, Google) are encrypted with AES-256-GCM under `LIFEOS_DATA_DIR/.secrets.json`. The `LIFEOS_VAULT_SECRET` (≥32 chars) is the decryption key — losing it makes the encrypted vault unreadable.
- **Auth**: Password hash stored as `salt:hex` scrypt output in `.env.local`. Never store plaintext passwords. Generated by `npm run setup:auth`.

## Architecture & Patterns

- **Modular monolith** with **Vertical Slice Architecture**. Bounded contexts (FinanceOS, StrategyOS, etc.) are strictly segregated but depend on the shared **43v3r.SDK**.
- **CQRS Mediator** (43v3r.SDK `src/sdk/cqrs.ts`): Commands/queries go through pipeline behaviors in this order: Authorization → Validation → Performance → Caching → Transaction → Handler. The `mediator.send()` method builds the chain recursively.
- **Mediator pipeline behaviors** (defined in `src/sdk/cqrs.ts`):
  - `AuthorizationBehavior` — checks requiredRoles on the request
  - `ValidationBehavior` — runs `FluentValidator` rules; wraps failures as Problem Details RFC 7807
  - `PerformanceBehavior` — logs warnings if >500ms
  - `CachingBehavior` — cache key from `cacheKey` property; TTL 120s (queries) or 300s (commands)
  - `TransactionBehavior` — auto-commits on success, rolls back on failure; only for commands (has `correlationId`)
  - `LoggingBehavior` — logs start/completion/failure
- **Domain primitives** (in `src/sdk/`): `Entity`, `AggregateRoot`, `ValueObject`, `BusinessRule`, `Result` (success/failure with Problem Details), `Pagination`, `Guid`, `DateTimeHelpers`.
- **FinanceOS** is mounted at `/api/finance`. Its routes use CQRS: `POST /api/finance/ledgers`, `POST /api/finance/journals`, `POST /api/finance/statements/import`, etc.
- **All AI prompts route through the AI Gateway Pipeline** (8 stages: intent detection → context retrieval → prompt builder → model router → tool execution → output validation → structured assembly → final response). No code should directly call Gemini/NVIDIA APIs.
- **Tenant isolation**: `tenantId` defaults to `"system-default"` on FinanceOS queries. FinanceOS commands accept it in the JSON body.
- **Read-only startup**: `server.ts` initDb is deliberately read-only — it never seeds, recovers, reconciles, or rewrites application records on startup.

## Testing Quirks

- Tests use **isolated `.test-data` directory** via `LIFEOS_DATA_DIR=.test-data`. The `npm test` script **rm -rf .test-data** first.
- **Do not share state across tests** — each test starts fresh.
- **SQLite migration test** (`tests/sqlite-migration.test.ts`) uses a fixture `db.json` then initializes SQLite; it verifies sessions are excluded from snapshots.
- **Production safety test** (`tests/production-safety.test.ts`) validates that missing/invalid config throws, and that all persistent paths derive from `LIFEOS_DATA_DIR`.
- **OCR test** checks that Linux skips Apple Vision and handles HEIC safely.
- Tests assert **no `saveDb` / `createLocalBackup` / `auditOperation` calls appear in auto-startup code** (production-safety.test.ts lines 51-68).

## Gotchas & Constraints

- **Production refuses to start** unless all required config vars are present and valid. `validateRuntimeConfiguration()` in `server/config.ts` checks: `APP_URL`, `LIFEOS_DATA_DIR`, `LIFEOS_AUTH_REQUIRED=true`, `LIFEOS_AUTH_EMAIL` (valid email format), `LIFEOS_AUTH_PASSWORD_HASH` (format `hex:hex` ≥64 chars), `LIFEOS_VAULT_SECRET` (≥32 chars, not a placeholder like "change", "replace", "example", "password", "secret").
- **`LIFEOS_VAULT_SECRET` must persist across restarts and deployments**. Changing or losing it makes the encrypted provider credential vault unreadable. Generate once with `npm run setup:auth` and retain it.
- **`.env.local` is gitignored** but must exist for production. It contains `LIFEOS_AUTH_REQUIRED=true`, `LIFEOS_AUTH_EMAIL`, `LIFEOS_AUTH_PASSWORD_HASH`, and `LIFEOS_VAULT_SECRET`.
- **Never commit real API keys, OAuth tokens, database credentials, or SMTP credentials**. The vault API (`/api/vault/save`) exposes provider presence only; raw values are never stored in SQLite, logs, backups, or AI prompts.
- **Server startup is read-only wrt authoritative records**. Schema migrations happen inside `initDb` with verification and rollback protection; application startup never seeds or cleans up user records.
- **OCR**: Apple Vision only on macOS. Linux skips Apple binaries and uses NVIDIA vision when configured. HEIC files remain saved with conversion guidance — do not expect OCR to produce text from HEIC on Linux.
- **CI quality pipeline** (`.github/workflows/quality.yml`): runs `npm ci`, `npm run lint`, `npm test`, `npm run build`, `npm run docs:check` on push and PR.
- **Route coverage**: `npm run docs:check` extracts every literal Express route from `server.ts` and the FinanceOS controller; it fails if any route is absent from `docs/API_REFERENCE.md`.
- **Express handler order matters**: duplicate `GET /api/goals` / `POST /api/goals` registrations are compatibility debt; REST-style routes under Goals are preferred.
- **Avoid `any` type** — the project enforces 100% strict typing. No use of `any` unless specifically permitted as a wildcard in generic constraints.
- **No circular dependencies between slices**, and no duplicated platform infrastructure (custom caching maps, database file writers, manual Gemini clients are strictly forbidden).
